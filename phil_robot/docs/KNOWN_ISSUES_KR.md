## 1. 지시한 자세(Ready, 각도 제어 등)를 유지하지 못하고 원위치로 돌아오는 현상

### 📝 증상
* "준비 자세로 가자", "팔 들고 있어", "특정 각도로 움직여" 등의 명령을 내렸을 때, 로봇이 지시받은 타겟 각도(자세)를 찍자마자 곧바로 이전의 기본 자세나 엉뚱한 자세로 스르륵 돌아와 버리는 현상.
* 특정 자세를 '유지(Hold)'하지 못함.

### 🔍 원인 분석 (가설)
1. **시뮬레이터(SIL) 측면의 타임아웃 캐시**:
   - 현재 실행 중인 파이썬 시뮬레이터 파이프라인(`SilCommandPipeReader.py`)에 이전에 존재했던 `IDLE_RETURN_SEC`(5초 유휴 시 초기 자세 복귀) 로직이 영향을 주고 있을 수 있습니다. (※ 해당 로직은 코드상으로는 방금 제거되었으나, 현재 백그라운드에 17분째 띄워져 있는 파이썬 프로세스에는 아직 이전 코드가 돌고 있어서 5초마다 리셋되고 있을 확률이 매우 높습니다.)
2. **C++ `Ideal` 상태의 기본값 강제 복귀**:
   - `AgentAction`을 통한 단순 `move`, `look` 등의 단일 행동(Action) 수행 후 C++ 상태 머신이 `Ideal`로 돌아오면, C++ 내부 루프가 로봇을 안전 자세(`homeAngle` 등)로 강제 회귀시키려는 로직이 숨어있을 수 있습니다.

## 2. "다시 연주해줘" 명령 시 준비 자세(r)만 취하고 연주(p)를 안 하는 현상

### 📝 증상
* 연주가 끝난 후 "다시 이전 곡 연주해 줘"라고 발화했을 때, 로봇이 준비 자세만 취하고 실제로 연주를 시작하지 않음.
* **로그 확인 결과**:
  ```python
  {'skills': ['ready_pose'], 'op_cmd': [], 'speech': '다시 연주할 준비가 되었어요. This Is Me를 시작할게요.', 'reason': '연주 요청에 따라 준비 자세 후 곡을 시작합니다.'}
  ```
  LLM 플래너가 의도는 제대로 파악했으나, 로봇에게 전달되는 최종 명령어로 연주(`p:TIM`)가 아닌 준비 자세(`r`) 단 하나만 생성함.

### 🔍 원인 분석 및 해결 방향
* **프롬프트 및 플래너 판단 오류**: 
  - LLM 플래너가 "연주를 하려면 일단 준비 자세로 가야지"라고 판단해서 `ready_pose` 스킬만 활성화하고, 정작 가장 중요한 `play_music` 스킬을 누락해 버린 것입니다.
* **C++ 자동화 로직과의 중복**:
  - 현재 C++ `DrumRobot::idealStateRoutine()` 코드를 보면, 연주 명령(`p:TIM`)이 들어왔을 때 로봇이 Ready 상태가 아니라면 **알아서 Ready 상태로 이동한 뒤 연주를 시작**하도록 자동화가 되어 있습니다.
  - **해결 방안**: 향후 Python 플래너의 프롬프트를 수정하여, 연주 요청이 오면 굳이 `ready_pose`를 섞지 말고 곧바로 `op_cmd: ['p:곡이름']`만 보내도록 지침(System Prompt)을 수정하면 깔끔하게 해결될 것입니다.
