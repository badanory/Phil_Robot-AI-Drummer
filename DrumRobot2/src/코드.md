## mutex의 차이만 있음

```
genAndPushAddStance()
  → getFinalMotorPosition()   // 현재 모터 위치
  → getAddStanceAngle()       // 목표 위치 (homeAngle / readyAngle)
  → pushAddStance()           // 사다리꼴 속도 프로파일로 직접 commandBuffer에 push
  → pushAddStanceDXL()        // DXL도 동일
```
악보 없이 그냥 "현재 위치 → 목표 위치"를 2초짜리 사다리꼴 프로파일로 직접 생성해서 바로 commandBuffer에 때려 박아요. IK도 없고 measureMatrix도 없어요. readyAngle은 스냅 포인트(SN 기준)로 IK를 미리 풀어서 저장해둔 값이에요.

  ### 공통점은 딱 하나
두 경우 모두 최종 목적지는 commandBuffer고, sendLoopForThread가 거기서 꺼내서 sendMotorFrame()으로 CAN 프레임을 보내는 건 똑같아요. 즉 생산 방식은 완전히 다르고 소비 방식은 동일한 구조예요.

## Home/Ready에서의 차이
pushAddStance()와 pushAddStanceDXL()에서 commandBuffer와 dxlCommandBuffer에 push할 때 mutex 보호 추가가 신버전에서 생긴 차이예요.
```
// 신버전 (문서5)
{
    std::lock_guard<std::mutex> lock(tMotor->bufferMutex);
    tMotor->commandBuffer.push(newData);
}

// 구버전 (문서6)
tMotor->commandBuffer.push(newData);
```
dxlCommandBuffer도 마찬가지예요. 로직 자체(사다리꼴 프로파일, 목표 위치 계산 등)는 동일하고 mutex만 추가된 거예요.


### Play에서의 차이
앞서 분석한 것처럼 훨씬 더 많이 바뀌었어요. mutex 추가뿐 아니라 producer-consumer 동기화, graceful stop, pause/resume, velocity modifier 처리 위치 변경, is_measure_end/is_last_measure 플래그 신설까지 구조 자체가 바뀌었어요.
